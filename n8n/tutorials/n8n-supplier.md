# How to review a supplier price increase and stockout in n8n

Import two versions of one supplier's catalog. Find the SKU whose cost rose as its stock fell to zero and decide whether to accept the updated catalog.

1. Import [Supplier](../workflows/n8n-supplier.json), follow the [connection guide](n8n-setup.md) and run the [stockout demo](../fixtures/supplier-observation.json). The fixed preview costs $0 in report events and routes to `DEMO_ONLY`. It leaves the production baseline untouched.
2. Give each supplier a separate production scope. Configure a parent workflow to receive the supplier's export-complete event or read the retailer's authorized export folder or API. For an HTTPS API, use a native HTTP Request GET with the origin and path set by the retailer, redirects disabled and a separate source credential bound only to that host. Use JSON rows normalized to the Actor's documented column mapping. Verify the export's own completion marker and original row count before forwarding it. Reject incomplete pages, missing rows and changes of supplier identity upstream.
3. On first use send the prior approved baseline and the new export as one item. The [synthetic custom envelope](../fixtures/supplier-custom-observation.json) shows `input.baseline.rows`, `input.incoming.rows`, `expectedIncomingRows` and an immutable `sequence`. Set a customer-approved cap of at least $0.85. The custom comparison requires an eligible Paid account and can buy **one $0.85 full report**. The default $0.01 demo cap blocks a custom report.
4. For the next export, send the new sequence, new `input.incoming` and the publisher's count, omitting `baseline`. The workflow retrieves the preceding successfully compared catalog from the last private Apify run. The integration accepts up to 5,000 incoming rows per observation. Respect the Actor's additional input and mapping limits.
5. `REVIEW_CATALOG_CHANGES` contains the report's exception SKUs and reasons. `CLEAN_CATALOG` means this comparison found no reportable exceptions. A complete report advances the comparison baseline even when it contains changes. The retailer decides whether to apply any of those changes to ordering or inventory. Missing data, partial reports or unexpected charges hold the baseline.
